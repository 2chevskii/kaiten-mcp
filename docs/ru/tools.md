# Справочник инструментов

Сервер предоставляет 14 инструментов, по одной паре чтения и изменения на домен.
Укажите операцию в `request.operation` и её параметры в `request.args`.

| Домен                                                              | Возможности                                                                           |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| `kaiten_workspace_read` / `kaiten_workspace_write`                 | Пространства, доски, пользователи, роли, группы, SCIM, справочные данные и аудит      |
| `kaiten_cards_read` / `kaiten_cards_write`                         | Поиск, детали, изменения, пакетные операции и история карточек                        |
| `kaiten_collaboration_read` / `kaiten_collaboration_write`         | Комментарии, ссылки, участники, теги, дочерние карточки, блокировки и зависимости     |
| `kaiten_checklists_read` / `kaiten_checklists_write`               | Чек-листы, пункты и шаблоны                                                           |
| `kaiten_custom_properties_read` / `kaiten_custom_properties_write` | Настройки и значения полей, справочники                                               |
| `kaiten_content_read` / `kaiten_content_write`                     | Документы, группы, схемы и вложения                                                   |
| `kaiten_workflows_read` / `kaiten_workflows_write`                 | Итерации, история спринтов, трудозатраты, автоматизации, Service Desk, SLA и webhooks |

Точные параметры каждой операции описаны в схемах `tools/list`.

```json
{"request": {"operation": "get_card", "args": {"card_id": 123}}}
```

Передайте этот запрос в `kaiten_cards_read`. См. [сценарии](./workflows.md), [вложения](./files.md) и [миграцию с v2](./api.md).

## Контракты результатов

Успешные вызовы возвращают результат в `structuredContent` и тот же JSON
текстовым элементом в `content`. Примеры показывают только структурированный
результат:

```json
{"item": {"id": 5, "full_name": "Алексей"}}
```

```json
{"items": [{"id": 1, "title": "Работа"}], "next_offset": null}
```

```json
{
  "items": [{"id": 123, "title": "Релиз", "board_id": 2, "column_id": 3}],
  "next_cursor": null
}
```

Сервер проверяет результат каждой операции по её схеме. В схемах инструментов перечислены форматы ответов.
В сокращённых представлениях необязательные поля присутствуют, только если их
вернул Kaiten; неизвестные upstream-поля удаляются. Операции с оболочкой `{result}`
сохраняют полный JSON. [Скачивание файлов](./files.md) также возвращает встроенный
бинарный ресурс. Отсутствующее поле отличается от явного `null`.

Инструменты чтения объявляют `readOnlyHint: true` и `idempotentHint: true`.
Инструменты записи объявляют `destructiveHint: true`, поскольку объединяют создание, изменение и удаление. Все инструменты записи объявляют `readOnlyHint: false`
и `idempotentHint: false`. У всех инструментов `openWorldHint: true`.
Аннотации информируют MCP-клиент; доступ в Kaiten определяется правами токена.

## Карточки

Читайте поля через `get_card`, ищите карточки через `search_cards`. Для записи используйте `create_card` или `update_card` с полями в `args.body`. Примеры приведены в [сценариях](./workflows.md).

Для фильтрации по проектам передайте `query.project_ids`
в `search_cards` с `mode: "native_page"` или в `scan_cards`. Передавайте UUID
проектов массивом или строкой с запятыми без пробелов. UUID проекта можно
взять из `result[].project_id` в результате вызова `list_card_baselines` для
карточки этого проекта. При запросе следующей страницы повторите фильтр.

## Существующие пользовательские поля

| Инструмент                                                        | Аргументы                                     | Действие                                               |
| ----------------------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------ |
| `kaiten_custom_properties_read` (`list_custom_properties`)        | `query?`, `limit?`, `offset?`                 | Найти определения с типами и настройками               |
| `kaiten_custom_properties_read` (`get_custom_property`)           | `property_id`                                 | Получить одно определение                              |
| `kaiten_custom_properties_read` (`list_select_values`)            | `property_id`, `query?`, `limit?`, `offset?`  | Найти ID и значения вариантов выбора                   |
| `kaiten_custom_properties_read` (`list_catalog_values`)           | `property_id`, `query?`, `limit?`, `offset?`  | Найти ID и значения каталога                           |
| `kaiten_custom_properties_read` (`list_custom_directories`)       | `query?`, `limit?`, `offset?`                 | Прочитать справочники с определениями полей            |
| `kaiten_custom_properties_read` (`list_custom_directory_records`) | `directory_id`, `query?`, `limit?`, `offset?` | Прочитать существующие записи со значениями            |
| `kaiten_custom_properties_write` (`set_card_properties`)          | `card_id`, `properties`                       | Записать или очистить непустой набор значений карточки |

Сначала прочитайте определение и нужные варианты. Ключи имеют вид
`id_<положительный ID поля>`. Значения используют JSON формат Kaiten:

| Поле                          | Пример значения                                           |
| ----------------------------- | --------------------------------------------------------- |
| Строка, URL, email, телефон   | `"значение"`                                              |
| Число или рейтинг             | `12`                                                      |
| Выбор или множественный выбор | `[12]` или `[12, 13]` — ID вариантов                      |
| Каталог                       | `"3"` — строковый ID значения                             |
| Пользовательский справочник   | `["12345678-1234-4234-8234-123456789abc"]` — UUID записей |
| Дата                          | `{"date":"2026-10-15","time":"12:00:00","tzOffset":180}`  |
| Очистка значения              | `null`                                                    |

Сервер проверяет ключи и JSON значения; Kaiten проверяет соответствие типу поля
и права. Поля, отсутствующие в `properties`, не отправляются. Управление определениями, вариантами и записями описано в [разделе полей](./custom-fields.md).

```json
{
  "card_id": 123,
  "properties": {
    "id_7": [12, 13],
    "id_8": null
  }
}
```
