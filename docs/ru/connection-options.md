# Подключение и ротация учётных данных

`KAITEN_API_VERSION` выбирает REST-префикс публичного клиента: `v1` (по умолчанию)
или `latest`. Настройка влияет на все обычные REST-запросы. SCIM сохраняет
`/scim/v2`, OAuth дополнений — `/api/v1` согласно их клиентам. Webhooks
используют переданный URL.

Для API задайте `KAITEN_TOKEN` или `KAITEN_TOKEN_FILE`. Для необязательного
OAuth дополнений — `KAITEN_ADDON_SECRET` или `KAITEN_ADDON_SECRET_FILE`.
Два непустых источника одной учётной записи вызывают ошибку. Переменная пути
не может быть пустой. Пробелы по краям статических значений удаляются.

Файлы содержат обычный UTF-8 токен с допустимыми пробелами по краям.
Относительные пути вычисляются от рабочей директории сервера при запуске.
Сервер передаёт публичный `TokenProvider`, который читает и обрезает файл
перед **каждым HTTP-запросом**. Токен можно менять без перезапуска, в том числе
между страницами итератора. Используйте атомарную замену файла, чтобы запрос
не прочитал частично записанный токен. Пути задаёт оператор сервера,
они не принимаются в аргументах инструментов.

Файлы читаются при запросе. Отсутствующий, недоступный или пустой файл вызывает
`CONFIGURATION_ERROR` до HTTP без раскрытия пути, системной ошибки и содержимого.
После исправления файла следующий вызов может пройти успешно. Клиент применяет
таймаут и отмену операции при получении токена и перед отправкой HTTP.

Пример окружения (не задавайте `KAITEN_TOKEN` при использовании файла):

```json
{
  "KAITEN_ORIGIN": "https://your-company.kaiten.ru",
  "KAITEN_TOKEN_FILE": "/absolute/path/to/kaiten-token",
  "KAITEN_API_VERSION": "latest"
}
```

В Windows используйте абсолютный путь с экранированными обратными слешами JSON,
например `C:\\secrets\\kaiten-token`. Настройки подключения не добавляют
инструменты MCP; их общее число остаётся равным 18.
