# Пользовательские справочники

Эти [расширенные операции](./api.md) используют `kaiten_custom_properties_read`
и `kaiten_custom_properties_write`; общее число остаётся равным 20. ID
справочников, полей и записей — UUID. Полный JSON-ответ upstream сохраняется
в `{result}`. API справочников помечен upstream как beta.

| Ресурс                   | Операции после `resource.`                                                                                                    | Аргументы                                                                                                                                                                                |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `customDirectories`      | `createCustomDirectory`, `getListOfCustomDirectories`, `getCustomDirectory`, `updateCustomDirectory`, `deleteCustomDirectory` | `body` для создания/изменения; `query?` для списка; `directory_id` для чтения/изменения/удаления                                                                                         |
| `customDirectoryFields`  | `createField`, `getListOfFields`, `getField`, `updateField`, `deleteField`                                                    | `directory_id`; `body` для создания/изменения; `field_id` для чтения/изменения/удаления; `include_author?`, `conditions?` для списка                                                     |
| `customDirectoryRecords` | `createRecord`, `getListOfRecords`, `getRecord`, `updateRecord`, `deleteRecord`, `getCardsLinkedToRecord`                     | `directory_id`; `body` для создания/изменения; `record_id` для чтения/изменения/удаления/связанных карточек; `query?` для списков; `response_profile?` для записи; `profile?` для чтения |

Создание справочника поддерживает описание, множественный выбор, права
редактирования, индекс отображаемого поля и начальные поля. Типы полей:
строка, число, дата, email, URL, телефон, флажок, список, пользователь, каталог,
связь со справочником и файл. Список полей на уровне справочника также принимает
привязки к пользовательским полям и другим справочникам. Отдельное создание
поля принимает имя/тип, порядок, обязательность и отображение; изменение —
имя, состояние, порядок и флаги.

**Изменение `fields` справочника заменяет полный список. Пропущенные поля
помечаются удалёнными.** Передавайте все сохраняемые поля. Необязательный
`expected_field_ids` должен сопровождать полный список и проверяет его
изменение (HTTP 409); это не общая проверка версии справочника. MCP принимает
этот документированный механизм upstream, хотя закреплённый клиент не включает
его в TypeScript-интерфейс тела; публичный метод передаёт его без изменений.
Изменение типа или привязки заполненного поля может быть отклонено с HTTP 400.

Запись использует JSON-словарь `values` с UUID полей в ключах. Значения ответа
возвращаются массивом. Пропущенные ключи сохраняются при изменении; `null`
очищает значение согласно типу поля. Редактирование записей требует прав
управления полями или `allow_editing: true` у справочника. Удаление поля/записи
помечает его удалённым; удаление записи также удаляет обратные связи справочников.
Чтение связанных карточек учитывает права настроенного токена.

Списки поддерживают флаги авторов/значений/полей/счётчиков, состояния, поиск и
offset-пагинацию там, где она доступна. У списка полей нет limit/offset.
Списки справочников/записей сортируются по времени создания без уникального
вторичного ключа; при одновременных изменениях offset не гарантирует экспорт
без повторов.

## Фильтры записей

`query.filters` принимает массив или объект с числовыми индексами в ключах.
Фильтр содержит `fieldId`, `fieldType`, `comparison`, необязательные `value` и
`searchByDisplayValue`. MCP проверяет сочетания типа/сравнения и преобразует
их в параметры вида `filters[0][fieldId]` через публичный метод клиента. Это
заменяет JSON-кодирование клиента, которое документированный endpoint не разбирает.

Текстовые поля поддерживают `eq`, `ne`, `contains`, `not_contains`,
`starts_with`, `ends_with`, `known`, `unknown`; числа/даты — `eq`, `ne`, `gt`,
`lt`, `known`, `unknown`; флажки — `true`, `false`; файлы — `known`, `unknown`.
Ссылочные поля поддерживают `eq`, `ne`, `known`, `unknown`; список, пользователь
и каталог также допускают `contains` при `searchByDisplayValue: true`.
Сравнения значений требуют непустого в смысле null/undefined `value`.
Состояния передаются массивами `active`, `inactive`, `removed`. Сохраняйте
`filter_operator` и остальные фильтры при переходе по страницам.

Поиск записей через `kaiten_custom_properties_read`:

```json
{
  "request": {
    "operation": "customDirectoryRecords.getListOfRecords",
    "args": {
      "directory_id": "12345678-1234-4234-8234-123456789abc",
      "query": {
        "filters": [
          {
            "fieldId": "22345678-1234-4234-8234-123456789abc",
            "fieldType": "string",
            "comparison": "contains",
            "value": "Alice"
          }
        ],
        "limit": 25,
        "offset": 0
      }
    }
  }
}
```
