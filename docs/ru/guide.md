# Подключение

Kaiten MCP подключает MCP-клиент к одной компании Kaiten через stdio. Нужны
Node.js 24 или новее, API-токен Kaiten и клиент, способный запускать локальный
MCP-сервер. Токен определяет доступные пространства, карточки и операции.

## 1. Установите сервер

```sh
node --version
npm install --global @2chevskii/kaiten-mcp --registry=https://registry.npmjs.org
npm root --global
```

Последняя команда выводит глобальный каталог `node_modules`. Найдите в нём
`@2chevskii/kaiten-mcp/bin/cli.js` и используйте абсолютный путь к этому файлу
в настройке ниже. Опубликованный пакет содержит собранный сервер и устанавливает
зависимости для его запуска.

Для запуска из исходников откройте [руководство разработчика](./development.md).
После сборки используйте `bin/cli.js` из каталога репозитория.

## 2. Настройте MCP-клиент

Для клиентов с JSON-конфигурацией `mcpServers` добавьте:

```json
{
  "mcpServers": {
    "kaiten": {
      "command": "node",
      "args": [
        "/absolute/path/to/node_modules/@2chevskii/kaiten-mcp/bin/cli.js"
      ],
      "env": {
        "KAITEN_ORIGIN": "https://company.kaiten.ru",
        "KAITEN_TOKEN": "YOUR_KAITEN_TOKEN"
      }
    }
  }
}
```

Замените путь, адрес компании и токен. Расположение конфигурации и способ её
перезагрузки зависят от MCP-клиента. Если клиент поддерживает настройки секретов
или окружения процесса, передавайте токен через них.

::: tip Пути в Windows
Используйте каталог из вывода `npm root --global`. В JSON допустимы прямые слеши,
например
`C:/Users/YOU/AppData/Roaming/npm/node_modules/@2chevskii/kaiten-mcp/bin/cli.js`.
Если клиент не находит Node.js 24+, задайте в `command` абсолютный путь
к исполняемому файлу этой версии Node.js.
:::

Прямой запуск через `node` работает независимо от текущего каталога и сохраняет
stdout свободным от служебного вывода npm. Пакет также предоставляет исполняемую
команду `kaiten-mcp` для клиентов, поддерживающих её запуск через PATH.

### Переменные окружения

| Переменная          | Обязательна | Значение                                                                                              |
| ------------------- | ----------- | ----------------------------------------------------------------------------------------------------- |
| `KAITEN_ORIGIN`     | Да          | Origin компании, например `https://company.kaiten.ru`; без пути API, учётных данных, query и fragment |
| `KAITEN_TOKEN`      | Да          | API-токен Kaiten; пробелы по краям удаляются                                                          |
| `KAITEN_TIMEOUT_MS` | Нет         | Тайм-аут операции в миллисекундах; по умолчанию `30000`, целое от `1` до `2147483647`                 |

Для компании Kaiten требуется HTTPS. Клиентская библиотека разрешает loopback
HTTP для локальных тестовых серверов. REST-запросы используют API v1.

Для нескольких компаний или токенов создайте отдельные записи серверов
с уникальными именами и собственными переменными окружения.

## 3. Проверьте подключение

Перезагрузите MCP-конфигурацию клиента и убедитесь, что доступны **44 инструмента**
с префиксом `kaiten_`. Попросите ассистента:

> Определи моего пользователя Kaiten и покажи доступные мне пространства.

Этот запрос использует `kaiten_get_current_user` и `kaiten_list_spaces` и проверяет
реальное чтение с настроенным токеном. Подключение MCP подтверждает запуск
процесса и обнаружение инструментов; первый вызов проверяет доступ к Kaiten.

Если процесс завершился или вызов вернул ошибку, откройте
[решение проблем](./troubleshooting.md). При запуске из терминала сервер может
выглядеть бездействующим, пока ожидает MCP-ввод.

## 4. Выберите сценарий

Начните с [поиска своих карточек](./workflows.md#мои-активные-карточки),
[чтения контекста](./workflows.md#разобраться-в-карточке) или
[создания карточки с чек-листом](./workflows.md#создать-карточку-и-чек-лист).
В [справочнике инструментов](./tools.md) перечислены все аргументы и действия.

Инструменты применяют изменения сразу при вызове. MCP-клиент определяет,
как показывать и подтверждать вызовы; аннотации сервера описывают чтение и
разрушительные операции. Kaiten проверяет права токена.

Поиск возвращает краткие сведения. Получайте детали карточки, комментарии и
пункты чек-листов отдельными инструментами. Списки по умолчанию содержат до
25 элементов, максимум — 100; продолжайте запросы, пока поле продолжения
не станет `null`.

## Поддерживаемые возможности

44 инструмента охватывают навигацию, карточки, комментарии, участников, теги,
чек-листы и существующие пользовательские поля. Можно читать определения полей,
варианты и справочники, а также задавать значения полей карточек.

Документы, вложения, учёт времени, автоматизации, администрирование, SCIM,
webhooks, редактирование определений полей и справочников выходят за рамки этой
версии. Сервер предоставляет инструменты через stdio; HTTP-транспорт,
MCP-ресурсы и prompts выходят за рамки этой версии.
