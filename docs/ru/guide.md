# Установка

Kaiten MCP подключает MCP-клиент к одной компании Kaiten через stdio. Нужны
Node.js 24 или новее, API-токен Kaiten и клиент, способный запускать локальный
MCP-сервер. Токен определяет доступные пространства, карточки и операции.

## 1. Проверьте Node.js

Используйте Node.js 24 или новее. npm и npx входят в поставку Node.js:

```sh
node --version
npm --version
```

## 2. Настройте MCP-клиент

Выберите команду CLI или файл конфигурации ниже. Примеры для Codex и Claude Code
добавляют сервер для вашего пользователя во всех проектах. Замените адрес компании
и токен, а записи добавьте в существующую конфигурацию. Не сохраняйте настоящие
токены в системе контроля версий. После настройки перезапустите клиент.

<ConnectionForm v-model:origin="origin" v-model:token="token" locale="ru" />

Команды CLI используют синтаксис POSIX shell.

### Codex

**CLI:**

```sh-vue
codex mcp add kaiten --env KAITEN_ORIGIN={{ shellOrigin }} --env KAITEN_TOKEN={{ shellToken }} -- npx --yes @2chevskii/kaiten-mcp
```

**Файл конфигурации:** добавьте в `~/.codex/config.toml`:

```toml-vue
[mcp_servers.kaiten]
command = "npx"
args = ["--yes", "@2chevskii/kaiten-mcp"]

[mcp_servers.kaiten.env]
KAITEN_ORIGIN = "{{ configOrigin.slice(1, -1) }}"
KAITEN_TOKEN = "{{ configToken.slice(1, -1) }}"
```

Для одного доверенного проекта используйте `.codex/config.toml` в его корне.
Проверьте регистрацию командой `codex mcp list`, а активные серверы — через `/mcp`
внутри Codex. Подробнее в
[официальном руководстве Codex по MCP](https://developers.openai.com/codex/mcp/).

### Claude Code

**CLI:**

```sh-vue
claude mcp add --scope user --transport stdio kaiten --env KAITEN_ORIGIN={{ shellOrigin }} --env KAITEN_TOKEN={{ shellToken }} -- npx --yes @2chevskii/kaiten-mcp
```

**Файл конфигурации:** добавьте запись в `mcpServers` верхнего уровня
в файле `~/.claude.json`:

```json-vue
{
  "mcpServers": {
    "kaiten": {
      "type": "stdio",
      "command": "npx",
      "args": ["--yes", "@2chevskii/kaiten-mcp"],
      "env": {
        "KAITEN_ORIGIN": {{ configOrigin }},
        "KAITEN_TOKEN": {{ configToken }}
      }
    }
  }
}
```

Для общей конфигурации проекта сохраните тот же JSON в `.mcp.json` в корне проекта
или используйте `--scope project` в команде CLI. Проверьте статус командой
`claude mcp get kaiten` или через `/mcp` внутри Claude Code. Подробнее в
[официальном руководстве Claude Code по MCP](https://code.claude.com/docs/en/mcp).

### Другие MCP-клиенты

Для клиентов с JSON-конфигурацией `mcpServers` добавьте:

```json-vue
{
  "mcpServers": {
    "kaiten": {
      "command": "npx",
      "args": ["--yes", "@2chevskii/kaiten-mcp"],
      "env": {
        "KAITEN_ORIGIN": {{ configOrigin }},
        "KAITEN_TOKEN": {{ configToken }}
      }
    }
  }
}
```

npx находит пакет и при необходимости загружает его в кеш npm.
`--yes` отключает запрос подтверждения установки, чтобы MCP-клиент мог
запустить сервер автоматически. Опубликованный пакет содержит собранный сервер.

Замените адрес компании и токен. Расположение конфигурации и способ её
перезагрузки зависят от MCP-клиента. Если клиент поддерживает настройки секретов
или окружения процесса, передавайте токен через них. Убедитесь, что Node.js
и npx доступны клиенту через PATH.

Для запуска из исходников откройте [руководство разработчика](./development.md).

### Переменные окружения

| Переменная            | Обязательна | Значение                                                                                              |
| --------------------- | ----------- | ----------------------------------------------------------------------------------------------------- |
| `KAITEN_ORIGIN`       | Да          | Origin компании, например `https://company.kaiten.ru`; без пути API, учётных данных, query и fragment |
| `KAITEN_TOKEN`        | Да          | API-токен Kaiten; пробелы по краям удаляются                                                          |
| `KAITEN_TIMEOUT_MS`   | Нет         | Тайм-аут операции в миллисекундах; по умолчанию `30000`, целое от `1` до `2147483647`                 |
| `KAITEN_CONTEXT_FILE` | Нет         | Пути к файлам контекста через запятую; читаются слева направо при запуске вместо автообнаружения      |

Для компании Kaiten требуется HTTPS. Клиентская библиотека разрешает loopback
HTTP для локальных тестовых серверов. REST-запросы используют API v1.

Для нескольких компаний или токенов создайте отдельные записи серверов
с уникальными именами и собственными переменными окружения.

### Личность и контекст подключения

Без дополнительных настроек «я» и «мои» означают аккаунт, возвращённый
`kaiten_navigation_read` (`get_current_user`). Ассистент получает инструкцию использовать его Kaiten ID
и не спрашивать подтверждение из-за отличий имени от профиля OpenAI, имени
пользователя ОС или nickname. «Мои задачи» по умолчанию используют
`responsible_ids`; явный запрос, например «созданные мной карточки», имеет приоритет.

Для служебного токена задайте `user_id` человека, чьи задачи считаются вашими.
Это не меняет аккаунт токена и его права: `kaiten_navigation_read` (`get_current_user`) всегда
возвращает настоящий аккаунт токена.

При необходимости создайте `.agents/kaiten-mcp.context.json` в проекте или профиле пользователя:

```json
{
  "user_id": 42,
  "my_tasks_role": "responsible",
  "instructions": "Сначала показывай просроченные задачи. Для работ по доставке выбирай доску доставки.",
  "spaces": [{"id": 10, "purpose": "Инженерные задачи"}],
  "boards": [
    {
      "id": 20,
      "space_id": 10,
      "purpose": "Работы по доставке",
      "guidance": "Выбирай для запросов по доставке; инфраструктура ведётся на другой доске."
    }
  ]
}
```

Без `KAITEN_CONTEXT_FILE` сервер загружает существующие файлы в таком порядке:

1. `<профиль пользователя>/.agents/kaiten-mcp.context.json`.
2. `.agents/kaiten-mcp.context.json` в корне проекта, затем в каждой директории
   до рабочей директории сервера. Ближайший файл загружается последним.

Корень проекта — ближайший предок (включая рабочую директорию) с файлом или
директорией `.git`, в том числе Git worktree. Если его нет, проверяются только
рабочая директория и профиль пользователя. Файл, найденный по обоим путям,
загружается один раз. MCP-клиент должен запускать сервер с рабочей директорией
проекта: каталог проекта из чата автоматически не определяется.
Отсутствующие автоматически обнаруживаемые файлы пропускаются.

Чтобы заменить автообнаружение, задайте `KAITEN_CONTEXT_FILE` в настройках окружения
рядом с токеном. Для Codex добавьте в секцию `[mcp_servers.kaiten.env]`:

```toml
KAITEN_CONTEXT_FILE = "C:/Users/me/.agents/kaiten-mcp.context.json,.agents/kaiten-mcp.context.json"
```

Явные пути загружаются слева направо; относительные разрешаются от рабочей
директории сервера. Все явно заданные файлы должны существовать. Пробелы по краям
путей удаляются; пустые элементы и пути с запятыми не поддерживаются. Чтобы отключить
наследуемый автоматический контекст, явно укажите файл с содержимым `{}`.

При слиянии последнее заданное значение `user_id` или `my_tasks_role` побеждает.
`instructions` объединяются в порядке загрузки; при противоречиях поздние инструкции
имеют приоритет. `spaces` и `boards` объединяются по `id`: поздняя запись полностью
заменяет предыдущую, включая необязательные поля. Отсутствующее поле сохраняет
унаследованное значение; пустой массив очищает соответствующий список. Правила
одинаковы для автообнаружения и явных путей.

Все поля JSON необязательны. `my_tasks_role` принимает `responsible` (по умолчанию),
`member` или `owner` и выбирает соответствующий фильтр поиска. Для пространства
или доски нужны положительный безопасный целочисленный `id` и непустой `purpose`.
`guidance` и `space_id` доски необязательны. Для `user_id` действуют те же ограничения
ID. Неизвестные поля, некорректные значения, пустые явные пути, недоступные файлы
и ошибочный JSON останавливают запуск с общим сообщением в stderr. Файлы читаются
один раз: после изменений перезапустите сервер. Каждая запись сервера может
использовать свои файлы. Объединённое содержимое передаётся модели: не храните в нём секреты.

Сервер передаёт правила в поле `instructions` при инициализации MCP и повторяет их
в описании `kaiten_navigation_read` (`get_current_user`) для клиентов, не передающих общие инструкции.
При инициализации дополнительных запросов к Kaiten нет. Клиент должен показывать
модели инструкции или описания инструментов; это не исправляет отсутствие
инструментов в каталоге клиента.

Явные указания пользователя имеют приоритет над настройками подключения. Если
область не задана, ассистент выбирает настроенное пространство или доску только
при однозначном соответствии назначению. Иначе он должен найти доступные области
и при необходимости уточнить выбор. Перед использованием настроенных ссылок
нужно проверить `kaiten_navigation_read` (`get_space`) или `kaiten_navigation_read` (`get_board`), а принадлежность доски
пространству — через `kaiten_navigation_read` (`list_boards`) с учётом пагинации. Если объект удалён
или недоступен, нужно сообщить о проблеме и запросить замену, не переключая область
молча. Запрос всех задач не должен незаметно ограничиваться доской по умолчанию.

Это инструкции модели, а не автоматическая подстановка фильтров или ограничение
доступа на сервере. Инструменты используют ID и фильтры, переданные клиентом;
права проверяет Kaiten. Сетевой проверки настроенных ссылок при запуске нет.
Фактическое поведение модели нужно проверять отдельно в вашем MCP-клиенте.

## 3. Проверьте подключение

Перезагрузите MCP-конфигурацию клиента и убедитесь, что доступны **16 инструментов**
с префиксом `kaiten_`. Попросите ассистента:

> Определи моего пользователя Kaiten и покажи доступные мне пространства.

Этот запрос использует `kaiten_navigation_read` (`get_current_user`) и `kaiten_navigation_read` (`list_spaces`) и проверяет
реальное чтение с настроенным токеном. Подключение MCP подтверждает запуск
процесса и обнаружение инструментов; первый вызов проверяет доступ к Kaiten.

Если процесс завершился или вызов вернул ошибку, откройте
[решение проблем](./troubleshooting.md). При запуске из терминала сервер может
выглядеть бездействующим, пока ожидает MCP-ввод.

## 4. Выберите сценарий

Начните с [поиска своих карточек](./workflows.md#мои-активные-карточки),
[чтения контекста](./workflows.md#разобраться-в-карточке) или
[создания карточки с чек-листом](./workflows.md#создать-карточку-и-чек-лист).
В [справочнике инструментов](./tools.md) перечислены все аргументы и действия.

Инструменты применяют изменения сразу при вызове. MCP-клиент определяет,
как показывать и подтверждать вызовы; аннотации сервера описывают чтение и
разрушительные операции. Kaiten проверяет права токена.

Поиск возвращает краткие сведения. Получайте детали карточки, комментарии и
пункты чек-листов отдельными инструментами. Списки по умолчанию содержат до
25 элементов, максимум — 100; продолжайте запросы, пока поле продолжения
не станет `null`.

## Поддерживаемые возможности

16 инструментов охватывают навигацию, карточки, родительские и дочерние связи, внешние ссылки, комментарии, участников, теги,
чек-листы и существующие пользовательские поля. Можно читать определения полей,
варианты и справочники, а также задавать значения полей карточек.

Также можно создавать, изменять и удалять пространства, доски, колонки,
подколонки и дорожки через [расширенные операции клиента](./api.md).

Профили пользователей, группы, роли, приглашения и доступ к пространствам
поддерживаются [операциями пользователей и доступа](./identity.md).

[SCIM](./scim.md) поддерживает пользователей, группы и типизированные patch-операции.

Документы, вложения, учёт времени, автоматизации,
webhooks, редактирование определений полей и справочников выходят за рамки этой
версии. Сервер предоставляет инструменты через stdio; HTTP-транспорт,
MCP-ресурсы и prompts выходят за рамки этой версии.
