# Установка и разработка

Kaiten MCP работает локально через stdio. Один процесс использует одну компанию
Kaiten и один API токен. Сервер предоставляет 44 инструмента для карточек,
навигации, комментариев, участников, тегов, чек-листов и пользовательских полей.

## Установка

Нужен Node.js 24 или новее. Авторизуйтесь в GitHub Packages с помощью personal
access token (classic), имеющего `read:packages` и доступ к пакету библиотеки:

```sh
npm login --scope=@2chevskii --auth-type=legacy --registry=https://npm.pkg.github.com
npm ci
npm run build
```

Файл `.npmrc` репозитория направляет scope `@2chevskii` в GitHub Packages. npm
сохраняет авторизацию в пользовательских настройках; секреты в репозиторий не
добавляются. Зависимость использует `edge`, публикуемый из `master` библиотеки.
Lockfile фиксирует установленную версию: сейчас `1.0.0-master-dbb18a1`.

Для явного обновления выполните команды и закоммитьте изменённый lockfile:

```sh
npm update @2chevskii/kaiten-client
npm run check
```

Сохраняйте `edge` в манифесте; lockfile содержит разрешённую версию. Переход на
стабильный релиз выполняется отдельным обновлением.

## Подключение клиента

Передайте процессу сервера переменные окружения:

| Переменная          | Назначение                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------------------- |
| `KAITEN_ORIGIN`     | Обязательный адрес компании, например `https://company.kaiten.ru`; без пути, логина, query и fragment |
| `KAITEN_TOKEN`      | Обязательный API токен Kaiten                                                                         |
| `KAITEN_TIMEOUT_MS` | Тайм-аут операции: по умолчанию `30000`, целое число от `1` до `2147483647`                           |

Для Kaiten требуется HTTPS. Библиотека допускает HTTP на loopback для локальных
тестов. Используется REST API `v1`.

Добавьте stdio сервер в настройки совместимого MCP клиента. Расположение файла
настроек зависит от клиента. При наличии настроек секретов/окружения передавайте
токен через них. Замените значения-заглушки:

```json
{
  "mcpServers": {
    "kaiten": {
      "command": "node",
      "args": ["C:/Users/YOU/source/kaiten-mcp/bin/cli.js"],
      "env": {
        "KAITEN_ORIGIN": "https://company.kaiten.ru",
        "KAITEN_TOKEN": "YOUR_KAITEN_TOKEN"
      }
    }
  }
}
```

Если PATH клиента выбирает другую версию Node.js, укажите абсолютный путь к
Node.js 24+. CLI работает из любого текущего каталога. Прямой запуск через `node`
сохраняет stdout для протокола. Пакет также объявляет команду `kaiten-mcp`;
глобальная установка для локальной разработки не требуется.

Stdio реализация SDK поддерживает современные MCP подключения и legacy
инициализацию. Диагностика направляется в stderr. Закрытие stdin, SIGINT и SIGTERM
завершают сервер; остановка процесса или отмена вызова отменяют HTTP запрос.

## Работа с инструментами

Типовой сценарий:

1. Вызвать `kaiten_list_spaces`, затем `kaiten_list_boards` с ID пространства.
2. Через `kaiten_get_board` получить ID колонок и дорожек.
3. Найти карточки через `kaiten_search_cards` или создать через `kaiten_create_card`.
4. Получить полное описание, участников, теги, значения полей и ссылки на чек-листы через `kaiten_get_card`.
5. Отдельными инструментами переместить карточку, добавить комментарий или отметить пункт чек-листа.
6. Архивировать карточку, восстановить её из архива или явно удалить.

Изменения выполняются при вызове инструмента. MCP аннотации описывают чтение и
разрушающие операции для клиента. Права определяются токеном Kaiten.

Поиск возвращает краткие карточки. Полное описание, текст комментариев и пунктов
чек-листа доступны через соответствующие инструменты. Списки возвращают 25
элементов по умолчанию, максимум 100 за вызов. Передавайте `next_cursor` или
`next_offset`, сохраняя исходные фильтры, пока продолжение не станет `null`.
После полной offset страницы возможна последняя пустая страница: эти API не
возвращают общее количество результатов.

Успешные ответы содержат `structuredContent` и такой же JSON в текстовом `content`.
Одна сущность находится в `item`; список — в `items` вместе с указателем
продолжения. Посторонние поля Kaiten не включаются в публичные представления.
Схемы аргументов и ответов доступны через MCP `tools/list`.

## Ошибки

Неверные аргументы отклоняются до запроса в Kaiten. Ошибки операций возвращают
`isError: true` и JSON с `code`, `message`, при наличии — HTTP `status`. Коды:
`KAITEN_HTTP_ERROR`, `INVALID_KAITEN_RESPONSE`, `NETWORK_ERROR`, `TIMEOUT`,
`CANCELLED`, `INTERNAL_ERROR`.

Автоматических повторов нет. Прерванная запись могла дойти до Kaiten; перед
повторным созданием проверьте карточку. В ошибках нет необработанных тел ответов,
токенов и заголовков авторизации.

## Разработка и проверки

```sh
npm run build:watch
npm run docs:dev
npm run check
```

`check` выполняет сборку, проверку типов тестов, `node:test`, ESLint, Prettier и
сборку документации на двух языках. Для отдельного запуска тестов сначала
соберите проект:

```sh
npm run build
npm test
```

Тесты запускают собранный CLI из другого каталога, подключают официальный MCP
клиент и через установленную библиотеку обращаются к локальному HTTP стенду.
Проверяются HTTP контракты всех инструментов, полный сценарий работы с карточкой,
пагинация, валидация, ошибки, отмена и завершение процесса. Рабочая компания
Kaiten не используется. Подключение конкретного настольного MCP приложения не
проверялось.

Используйте выделенную ветку и небольшие Conventional Commits. Обновляйте оба
языка документации при изменении интерфейса. Правила репозитория находятся в
корневом `AGENTS.md`.

## Границы версии

Разработка, коммиты и документация пока локальные. Документы, вложения, учёт
времени, автоматизации, администрирование, SCIM, webhooks, HTTP транспорт, MCP
resources и prompts в эту версию не входят. Определения пользовательских полей,
варианты и справочники доступны для чтения; значения можно присваивать карточкам.
Редактирование определений и справочников отложено.
