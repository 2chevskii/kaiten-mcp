# OAuth дополнений

Публичный `AddonOAuthClient` доступен через существующие инструменты навигации.
Общее число инструментов остаётся равным 18.

| Операция                  | Инструмент                | Аргументы                            |
| ------------------------- | ------------------------- | ------------------------------------ |
| `addonOAuth.getToken`     | `kaiten_navigation_read`  | `addon_uid`, `user_id`, `company_id` |
| `addonOAuth.refreshToken` | `kaiten_navigation_write` | Тот же ключ токена                   |

Задайте `KAITEN_ADDON_SECRET` в окружении сервера. Этот секрет авторизует две
операции на настроенном `KAITEN_ORIGIN`; обычные REST- и SCIM-запросы используют
`KAITEN_TOKEN`. Секрет дополнения нельзя передать аргументом инструмента.
Настроенное значение должно быть непустым после удаления пробелов по краям.
Без секрета обе операции видны, но возвращают `CONFIGURATION_ERROR` до HTTP.
Обычные настройки подключения сервера по-прежнему обязательны.

Полный ответ возвращается в `{result}`: `has_token: false` с необязательным
`domain` либо `has_token: true` с `access_token`, `expires_at` и необязательным
`domain`. Возврат access token предусмотрен контрактом; результат и история
вызовов содержат учётные данные. Секрет дополнения и приватные тела ошибок
не включаются в ошибки и диагностику. Действуют таймаут и отмена MCP;
обновление токена автоматически не повторяется.

```json
{
  "request": {
    "operation": "addonOAuth.getToken",
    "args": {"addon_uid": "your-addon-uid", "user_id": 5, "company_id": 7}
  }
}
```

Метаданные дополнений и объявления браузерного SDK клиента — типы TypeScript.
Браузерную среду предоставляет Kaiten; эти token endpoints не размещают
дополнение и не предоставляют UI авторизации OAuth.
