# Документы, группы и схемы

Сервер предоставляет **18 инструментов**. Чтение документов использует
`kaiten_documents_read`, изменения — `kaiten_documents_write`, в пределах
ограничения в 20. Эти [расширенные операции](./api.md) возвращают полный
JSON-ответ клиента в `{result}`.

| Ресурс            | Операции после `resource.`                                                                                                                 | Аргументы                                                                                                                              |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `documents`       | `createNewDocument`, `retrieveDocument`, `retrieveListOfDocuments`, `updateDocument`, `removeDocument`, `iterate`                          | `body` для создания/изменения; `document_uid` для чтения/изменения/удаления; `query?` для списка/обхода; `max_items?` для обхода       |
| `documentGroups`  | `createNewDocumentGroup`, `retrieveDocumentGroup`, `retrieveListOfDocumentGroups`, `updateDocumentGroup`, `removeDocumentGroup`, `iterate` | `body` для создания/изменения; `document_group_uid` для чтения/изменения/удаления; `query?` для списка/обхода; `max_items?` для обхода |
| `documentSchemas` | `getDocumentDataSchema`                                                                                                                    | Строковый `schema_version`, необязательный `format`: `draft-06` или `prosemirror`                                                      |

## Содержимое и редактирование

Создание документа требует числовой `sort_order`; заголовок, родитель, роль,
UID/версия клонирования и ключ необязательны. Создайте/клонируйте документ, затем
измените содержимое через `documents.updateDocument`. Изменение предоставляет
полный контракт: содержимое, заголовок/порядок, родитель/доступ, дата/версия
публикации, версия резервной копии, флаги сайта, перенаправление, ширина
содержимого, ключ/slug, значки и периоды уведомлений. `published_version`
принимает число, `null` или `"current"`. Требуется хотя бы одно изменение;
пропущенные поля не добавляются, допустимые явные null сохраняются.

`data` — дерево ProseMirror: корень `type: "doc"` с массивом `content`. Узлы
требуют непустой `type`; поддерживают JSON `attrs`, вложенный `content`, `marks`
и `text`. Метки требуют тип и допускают JSON-атрибуты. Текстовый узел требует
непустой текст. Неизвестные структурные поля и неверные вложенные узлы
отклоняются до HTTP. Имена узлов/меток и семантика атрибутов зависят от версии
схемы Kaiten документа; запросите схему этой версии, чтобы узнать их. Backend
проверяет содержимое по версии. Оба формата схем и расширенные поля их ответов
сохраняются.

Создание группы поддерживает заголовок, родителя, роль, порядок и ключ.
Изменение также предоставляет доступ, hostname/перенаправление, значок,
видимость на сайте, ленту новостей и индексный документ, с обязательными
сочетаниями полей клиента. Удаление документов/групп использует публичные DELETE.

## Пагинация

Списки предоставляют все фильтры клиента, проекции текста, флаги роли/preview и
параметры пагинации. Версия 1/по умолчанию возвращает массив; версия 2 —
`{result: [...], position: "..."}` внутри внешней обёртки. Сохраняйте фильтры и
передавайте `position` в `query.start_position`; пустая позиция завершает поиск.
Типы ID и метаданных сохраняются согласно версии upstream без преобразования.

Оба `iterate` используют обход курсоров v2 клиента и возвращают
`{result: {items, truncated}}`. `max_items` по умолчанию равен 100, диапазон
1–1 000; возможен один дополнительный элемент, курсор продолжения отсутствует.
Для возобновляемых страниц используйте операции списков. Отмена и таймаут
охватывают весь обход.

Запись содержимого через `kaiten_documents_write`:

```json
{
  "request": {
    "operation": "documents.updateDocument",
    "args": {
      "document_uid": "document-uid",
      "body": {
        "data": {
          "type": "doc",
          "content": [
            {
              "type": "paragraph",
              "content": [{"type": "text", "text": "Specification"}]
            }
          ]
        }
      }
    }
  }
}
```
