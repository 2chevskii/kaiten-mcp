# Сценарии работы

Примеры показывают имена инструментов и JSON-аргументы вызовов MCP-клиента.
Передайте текст запроса ассистенту или используйте аргументы в клиенте
с интерфейсом вызова инструментов. Все ID условные: замените их значениями,
полученными из вашей компании.

## Мои активные карточки

> Найди мои активные карточки, сгруппируй по доскам и сначала покажи просроченные.

1. Вызовите `kaiten_get_current_user` с `{}` и прочитайте `item.id`.
2. Передайте этот ID как фильтр владельца в `kaiten_search_cards`:

```json
{
  "owner_ids": [5],
  "archived": false,
  "states": [1, 2],
  "limit": 25
}
```

Состояние `1` — очередь, `2` — в работе, `3` — выполнено. Добавьте
`overdue: true`, чтобы найти только просроченные карточки. Для конкретной доски
получите её ID через `kaiten_list_spaces` и `kaiten_list_boards`, затем добавьте
`board_id`.

Для владельца, участника и ответственного предусмотрены отдельные фильтры:
`owner_ids`, `member_ids` и `responsible_ids`. Выбирайте связь, указанную
в запросе. Для объединения этих связей выполните отдельные поиски и удалите
дубликаты по ID карточки.

### Продолжение поиска

Если ответ содержит `next_cursor: "offset:25"`, повторите исходные фильтры
и добавьте `cursor`:

```json
{
  "owner_ids": [5],
  "archived": false,
  "states": [1, 2],
  "limit": 25,
  "cursor": "offset:25"
}
```

Остановитесь, когда `next_cursor` станет `null`. После полной последней страницы
может понадобиться дополнительный пустой запрос. Карточки упорядочены по ID;
изменение подходящих карточек между запросами может сдвинуть страницы.
Курсор содержит позицию, поэтому исходные фильтры нужно сохранять самостоятельно.

Другие инструменты списков возвращают `next_offset`. Передавайте это число
как `offset`, сохраняя фильтры и `limit`, пока `next_offset` не станет `null`.

## Разобраться в карточке

> Прочитай карточку 123, комментарии и чек-листы. Опиши блокер и незавершённые задачи.

| Шаг                  | Инструмент             | Аргументы                          |
| -------------------- | ---------------------- | ---------------------------------- |
| Описание и ссылки    | `kaiten_get_card`      | `{"card_id":123}`                  |
| Обсуждение           | `kaiten_list_comments` | `{"card_id":123,"limit":100}`      |
| Чек-лист из карточки | `kaiten_get_checklist` | `{"card_id":123,"checklist_id":8}` |

Прочитайте все страницы комментариев и каждый чек-лист из карточки.
`kaiten_list_checklists` также позволяет получить ссылки на чек-листы.
Детали карточки содержат ссылки, а `kaiten_get_checklist` возвращает текст
пунктов и отметки выполнения. Краткие результаты поиска не содержат описания
и обсуждения.

## Создать карточку и чек-лист

> Создай карточку релиза на доске «Доставка» с чек-листом «Реализация».

Найдите пространство и доску. Через `kaiten_get_board` получите допустимые
ID колонок и дорожек этой доски. Затем вызовите `kaiten_create_card`:

```json
{
  "title": "Подготовить релиз",
  "board_id": 2,
  "column_id": 3,
  "lane_id": 4,
  "description": "## Цель\nВыпустить согласованный релиз.",
  "due_date": "2026-10-15"
}
```

Для следующих вызовов используйте полученный `item.id`. Для карточки `123`
вызовите `kaiten_create_checklist` с
`{"card_id":123,"name":"Реализация"}`. Передайте полученный ID чек-листа
в `kaiten_add_checklist_item`:

```json
{
  "card_id": 123,
  "checklist_id": 8,
  "text": "Проверить описание релиза",
  "responsible_id": 5
}
```

Для выполнения созданного пункта вызовите `kaiten_update_checklist_item`:

```json
{
  "card_id": 123,
  "checklist_id": 8,
  "item_id": 13,
  "changes": {"checked": true}
}
```

Каждый вызов — отдельная операция. Если следующий шаг завершился ошибкой,
предыдущие успешные изменения остаются в Kaiten. После тайм-аута создания
проверьте существующие карточки или пункты перед повтором; сервер
не повторяет запросы автоматически.

## Переместить, изменить или архивировать карточку

Передайте в `kaiten_move_card` все четыре ID расположения:

```json
{"card_id": 123, "board_id": 2, "column_id": 30, "lane_id": 40}
```

Сначала прочитайте целевую доску, чтобы получить её колонки и дорожки.
Для редактирования содержимого используйте `kaiten_update_card` с непустым
объектом `changes`:

```json
{
  "card_id": 123,
  "changes": {"description": null, "due_date": "2026-10-15"}
}
```

Пропущенные поля сохраняют значения. `null` очищает поддерживаемые поля;
см. [изменяемые поля](./tools.md#карточки). Для архивации вызовите
`kaiten_archive_card`, для восстановления — `kaiten_restore_card`,
оба с `{"card_id":123}`. Архивация меняет условие карточки; состояние
«очередь / в работе / выполнено» хранится отдельно.

## Назначить участников и пользовательские поля

Для добавления пользователя вызовите `kaiten_add_card_member` с `card_id`
и `user_id`. Чтобы назначить участника ответственным, получите `id` связи
из `kaiten_list_card_members` и передайте его как `member_id`
в `kaiten_update_card_member_role` с `type: 2`.

Для пользовательских полей:

1. Прочитайте `kaiten_get_board`, чтобы узнать настройки полей доски.
2. Найдите поле через `kaiten_list_custom_properties` и прочитайте определение
   через `kaiten_get_custom_property`.
3. Получите существующие варианты через `kaiten_list_select_values`,
   `kaiten_list_catalog_values` или инструменты справочников в зависимости от типа.
4. Вызовите `kaiten_set_card_properties` с найденными ID:

```json
{"card_id": 123, "properties": {"id_7": [12, 13], "id_8": null}}
```

Здесь `id_7` — пример поля выбора, а `id_8` очищается. Сервер проверяет ключи
и JSON-значения; Kaiten проверяет типы полей и права. См.
[форматы значений](./tools.md#существующие-пользовательские-поля).
